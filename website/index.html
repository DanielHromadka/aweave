Install

Many agents. One repository. No pile-ups.

aWeave gives every AI agent its own workspace, tells them about overlapping work before they write conflicting code, and merges through a queue that keeps trunk green. On top of git, with an MCP server.

Install Source on GitHub

Free and open source, GPL-3.0. macOS, Linux, Windows (experimental).

Why

Git was built for one person on one branch.

Ten agents on one repository break its assumptions in three places at once.

They trip over each other

One working copy per checkout. Agents overwrite each other's files and fight over index.lock.

Conflicts arrive last

Two agents spend an hour on the same function and find out at merge time. Nobody could say “I'm on it”.

Trunk breaks, and nobody knows why

The last merge lands on code nobody tested, and the commit names an author, not the agent or task behind it.

How it works

Four commands an agent learns in a minute.

  1. 1

    A workspace per agent

    An isolated git worktree on its own branch, created in one command. aWeave recognises it from the current directory.

    $ aweave --agent claude-1 ws new auth-timeout
.aweave/ws/auth-timeout
  2. 2

    Say what you'll touch, first

    An intent names files, folders or globs. If another agent is already there, you hear it now, not at merge time.

    $ aweave intent add "Rate-limit login" --scope src/auth
intent #2 declared: src/auth
! auth-timeout and login-ratelimit intend to
  change the same paths: src/auth/session.rs
  3. 3

    Snapshot often

    Checkpoint commits carry the agent, workspace, task and intents as trailers. A crashed agent loses minutes, not hours.

    $ aweave snapshot -m "Retry refresh" --task SHOP-142
ec6487f7a0da Retry refresh
  4. 4

    Propose, and let the queue merge

    Rebased onto trunk, verified, fast-forwarded. A conflict or a red test comes back to the agent; trunk does not move.

    $ aweave propose
merged 1 commit(s) from auth-timeout into main
released intents #1

Overlap radar

Every pair of agents, checked all the time.

aweave status, aweave check (exit code 2 for scripts) and every new intent compare what each workspace has changed with what every other one intends to change.

intent / intent

Two plans collide

Both agents declared paths that overlap, even for files that do not exist yet. The cheapest moment to reschedule.

change / intent

Someone is already in there

One agent has edited files another one is about to work on. The second one should sync after the first merges.

change / change

Both edited the same file

Not necessarily a conflict yet, but the queue will tell. Semantic, per-function merge is next on the road map.

Integration queue

Trunk only moves to commits that passed.

  • One at a time. Proposals from parallel agents line up behind a file lock.
  • Rebased in its own worktree, so the agent's checkout is never touched mid-work.
  • Your verify command (cargo test, npm test, a linter) runs on the exact result.
  • Compare-and-swap on trunk. If someone pushed meanwhile, nothing is overwritten.

MCP server

Agents use it as tools, not as text to parse.

Start each agent in its own workspace with its own name. aweave mcp speaks MCP over stdio.

$ cd "$(aweave --agent backend-1 ws new backend-1)"
$ claude mcp add aweave -- aweave mcp --agent backend-1

A prompt line that works well: “Before editing, call aweave_intent_declare for the files you will touch. If it reports overlaps, tell me instead of editing. Snapshot after each step and finish with aweave_propose.”

  • aweave_statusWorkspaces, changes, intents, overlaps
  • aweave_workspace_createIsolated workspace for a task
  • aweave_intent_declareClaim paths, get overlaps back
  • aweave_intent_releaseDrop a claim
  • aweave_snapshotCheckpoint with provenance
  • aweave_syncRebase onto the current trunk
  • aweave_proposeRebase, verify, merge
  • aweave_eventsWhat happened since you last looked

Provenance

Every commit says which agent, and why.

Plain git trailers, so they survive every host and show up in git log --grep. The event log records the rest: who declared what, which overlaps appeared, which proposals failed and with what output.

Road map

Coordination first. A new version control core after.

  1. M0 · available

    Coordination on top of git

    Workspaces, intents and the overlap radar, snapshots with trailers, the integration queue, the event log and the MCP server.

  2. M1

    Semantic merge

    Diffs and conflicts per function and type with tree-sitter, so independent edits to one file merge on their own. Intents on symbols.

  3. M2

    Signed provenance

    Model, tools and test results per change, signed. Revert everything one agent or task did in one command.

  4. M3

    Own store and operation log

    Copy-on-write workspaces in milliseconds, conflicts as data, undo for any operation, a two-way bridge to git.

Get aWeave.

One binary. Run aweave init in any git repository.

curl -fsSL https://aweave.pages.dev/install.sh | sh

The script picks the build for your system and checks its SHA-256. Or: cargo install --git https://github.com/DanielHromadka/aweave
